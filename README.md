# Финансовый дом — Telegram-бот учёта финансов (MVP)

Бот для учёта доходов и расходов: текст, голос, фото чека. Стек: aiogram 3,
Supabase (Postgres), Groq (LLM + Whisper + Vision), Redis (сессии PIN и FSM),
Render + UptimeRobot.

## ⚠️ Главное правило ввода

**Всегда указывай валюту рядом с суммой.** Без этого бот не может отличить
сумму от количества или массы.

- ✅ `кофе 150р`, `зарплата 100000₽`, `такси 350р`, `lunch $12`
- ❌ `сахар 5` — непонятно: 5 килограмм или 5 рублей?

Поддерживаемые обозначения валюты: `р`, `руб`, `₽`, `$`, `usd`, `€`, `eur`.

## Установка

⚠️ В репозитории есть файл `.python-version` (закрепляет Python 3.12) —
не удаляй его. Без него Render на новых сервисах подхватывает самую свежую
версию Python (сейчас 3.14), а для нее у некоторых зависимостей
(`pydantic-core`, тянется через `aiogram`) ещё нет готовых собранных
пакетов — pip пытается собрать их из исходников через Rust/Cargo, а
песочница сборки на Render это запрещает, деплой падает на этапе
установки зависимостей. Если уже есть развёрнутый сервис и появился этот
файл впервые — на Render нужно **Clear build cache & deploy**, обычного
редеплоя может быть недостаточно (кеш от старой версии Python).

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # заполнить токены
```

Выполнить `schema.sql` в Supabase SQL editor.

### Переменные окружения (дополнительно к базовым)

- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — тот же OAuth-клиент, что у
  PixKeep (Google Cloud проект общий, приложения разные)
- `GOOGLE_OAUTH_REDIRECT_URI` — свой домен, напр.
  `https://<этот-render-сервис>.onrender.com/oauth/callback` (ОТДЕЛЬНЫЙ от
  PixKeep, т.к. другой Render-сервис)
- `CRON_SECRET` — произвольная строка; защищает `/cron/daily` от
  посторонних вызовов (см. ниже)

### Ежедневный cron (напоминания о пробеге + месячная статистика)

Настрой внешний пинг (UptimeRobot, как и для `/health`) раз в день на:
```
GET https://<этот-домен>.onrender.com/cron/daily?secret=<CRON_SECRET>
```
Один пинг закрывает обе задачи — каждая сама решает, нужно ли что-то делать
именно сегодня: напоминание про пробег — раз в неделю на машину (трекается
независимо для каждой), статистика — раз в отчётный период на пользователя
(по его собственному дню начала периода, не календарный конец месяца).

### Устойчивость (как в остальных твоих ботах)

- **Автоперезапуск polling** — если `dp.start_polling()` упадёт по сетевому
  сбою и т.п., бот сам перезапустит его через 5 сек, а не умрёт целиком
  (`run_polling_with_retry` в `main.py`).
- **Supabase keep-alive** — фоновая задача внутри бота стучится в Supabase
  каждые `SUPABASE_KEEPALIVE_INTERVAL_SECONDS` (по умолчанию 6 часов),
  независимо от внешних cron-пингов — free-tier проекты Supabase
  приостанавливаются после ~7 дней без обращений к API.

Запуск:

```bash
python main.py
```

| Файл | Назначение |

| `parser.py` | Парсинг суммы/валюты/типа из текста |
| `groq_client.py` | LLM-категоризация, Whisper, Vision (чеки) |
| `supabase_client.py` | Вся работа с БД |
| `pin_handler.py` | Хеш PIN + сессии в Redis |
| `states.py` | FSM-состояния |
| `keyboards.py` | Inline-клавиатуры |
| `middlewares.py` | Гейт по PIN-коду |
| `start.py` | `/start` + онбординг |
| `pin_auth.py` | Проверка PIN при входе |
| `input_handler.py` | Текст/голос/фото — основной ввод трат |
| `report.py` | `/report` |

## Что входит в MVP

- Три способа ввода: текст, голос (Whisper), фото чека (Vision — только сумма)
- Категоризация: ключевые слова → память (`category_map`) → Groq LLM
- Ambiguous-флоу: если категория не ясна — inline-кнопки, выбор запоминается
- `/report`, `/history`, `/categories`, `/family`, `/undo`, `/settings`
- Онбординг: валюта → день периода → сумма на руках (опц.) → Google Drive
  (обязательно) → машина(ы) (опц., цикл добавить/готово) → PIN (опц.)
- Семейный бюджет: общий кошелёк (одна Google-таблица на семью, владелец —
  инициатор `/family`), без расчёта "кто кому должен"
- PIN-код (Supabase-хеш + Redis-сессия 5 мин, блокировка после 3 попыток)
- Реакция 👍 вместо текстового подтверждения записи
- **Хранение**: реальные транзакции — в Google Sheets владельца (не в
  Supabase!). Supabase — только метаданные (users/категории/семья/PIN).
- **Авто-траты**: категория «Авто» → отдельный лист с типом (Заправка/ТО/
  Ремонт/Прочее), машиной, пробегом; поддержка нескольких машин на семью с
  дизамбигуацией через кнопки
- **Пробег без валюты**: «пробег опель 305000 км» — отдельная ветка, не
  требует указания валюты
- **Еженедельные напоминания о пробеге** — по каждой машине отдельно (внешний
  cron-пинг на `/cron/daily`, см. `reminders.py`), кнопка «Без изменений»
- **Отслеживание техжидкостей** — предупреждение при приближении к интервалу
  замены (масло/антифриз/тормозная жидкость/фильтр/свечи), без привязки к
  конкретному двигателю; срабатывает при каждой новой записи пробега
- **`/cars`** — список машин с удалением (мягкий архив + выгрузка полной
  истории в отдельный файл), добавление новой
- **`/carstats`** — статистика по машине за текущий период (пробег +
  разбивка трат по типам); плюс автоматическая рассылка в последний день
  периода (тот же `/cron/daily`) — всем, кто делит эту таблицу

## Не входит в MVP (бэклог)

Экспорт Excel/PDF отдельно от Sheets, шаблоны команд, `/edit`, `/find`,
графики в отчётах, средний чек, регулярные платежи, интеграции с банками,
персонализация интервалов замены жидкостей под конкретный двигатель (сейчас
общие ориентиры по типу жидкости, не по марке/модели).

  актуальные названия моделей в консоли Groq перед деплоем.
- `PIN_SALT` уже вынесен в `.env` — обязательно задай свою случайную строку
  перед первым запуском в проде (не используй дефолт из кода).
- Reactions (`set_message_reaction`) требуют Bot API 7.0+ — проверить версию
  aiogram/Telegram Bot API на момент деплоя.
- Для группы более 2 человек в `/family` текущая схема уже поддерживает N
  участников (family_members — многие-ко-многим), тестировать на 2 сначала.
